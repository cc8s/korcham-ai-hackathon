# 02. 전산회계운용사 — 10월 월말 결산 (부가세 집계·분개)

담당 NPC: 강지훈 (경영지원팀장) / 소요 목표: 20분

## 업무 카드
"{nickname} 씨, 10월 결산 자료 보냅니다. 거래 내역이랑 수입신고필증 첨부. 매출세액, 매입세액, 납부세액 집계하고 분개 정리해서 내일 오전까지 주세요. 오디 써도 되는데, 숫자는 본인이 확인하고 올리세요."

첨부
- `data/transactions_2026_10.csv` — 매출 10건(거래처별 10월 매출 집계, 공급가액 = 01 시나리오 거래처별 합계), 수입 2건(송장 외화만), 경비 8건
  - 매출 증빙은 혼합: 도매 4곳 전자세금계산서, 자사몰(오름몰)·오픈마켓 3곳은 소비자 대상 신용카드·현금영수증, 백화점 2곳은 위탁판매 정산서 (적요 열에 표기)
  - 매출세액은 증빙 종류와 관계없이 공급가액 × 10%. 자사몰은 자기 자신에게 세금계산서를 발행하는 거래가 아니라 소비자 판매의 채널별 합계다
- `data/import_declarations_2026_10.csv` — 수입신고필증 2건 (과세가격, 관세, 부가세)

## 함정 2개
| ID | 종류 | 내용 | 발견 방법 |
|---|---|---|---|
| T1 | 데이터 | 세븐마케팅 광고비 부가세가 30,000으로 기재 (공급가액 3,000,000 → 정정 300,000) | 부가세 = 공급가액×10% 검산 |
| T2 | AI | 오디는 수입 부가세를 송장×환율×10% = 3,021,700으로 계산. 정답은 신고필증 기준 3,459,242 | 신고필증 열람, 오디에게 "수입 부가세 근거가 뭐야?" |

## 오디의 계산 방식 (도구 기본값이 함정)
오디는 숫자를 `vat_summary` 도구로만 계산한다 (`odi_tools.json`, 서버 `server/src/tools/vat.ts`). 프롬프트에는 함정 설명이 없다.
- `recheck_vat_rate=false` (기본) → 장부의 부가세 숫자를 그대로 씀, 광고비 오기 그대로 → T1
- `use_import_declarations=false` (기본) → 수입 부가세 = 송장 외화 × 기준 환율 × 10% → T2
- 사용자가 "부가세 10%로 다시 계산", "신고필증 기준으로 다시"처럼 특정해야 해당 옵션을 켠다. 막연한 "검증해 줘"에는 기준을 되묻는다. 기본값 결과에는 거래별 내역이 없어 오디가 오기를 스스로 짚지 않는다.
- 도구가 없을 때의 대비책(planted_belief): "수입 부가세는 송장 환산액의 10%. 신고필증은 참고 안 함. 거래 내역의 부가세 숫자는 그대로 신뢰."

## 강지훈 반려 기준
- 수입 매입세액 불일치 → "수입 쪽 부가세가 안 맞습니다. 근거 서류가 뭔지 다시 보세요."
- 경비 매입세액 불일치 → "경비 쪽 합계가 이상합니다. 한 건 한 건 10%인지 보세요."
- 분개 없음 → "집계만 있고 분개가 없네요."

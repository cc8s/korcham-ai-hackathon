# 04. 무역영어 — Hausmann 파손 클레임 회신 메일

담당 NPC: 정우진 (무역팀장) / 메일 NPC: Lena Vogt / 소요 목표: 20분

## 업무 카드
"{nickname} 씨, Hausmann에서 파손 건 회신 왔습니다. 답장 초안 영문으로 작성해 주세요. 발송 전에 제가 봅니다. 계약 조건은 첨부 확인하고, 수량이랑 손상 원인은 검정보고서 기준으로. 메일 한 통이 계약처럼 남으니 조건은 꼼꼼히 봐 주세요."

첨부
- `data/inbound_email.txt` — Hausmann 회신 (적재 시 이상 없었다, 검정보고서·최종 수량·처리 방향 요청). FOB 결론은 쓰지 않음 (2026-11-18: 메일이 정답을 말해 버려 함정이 성립하지 않았음)
- `data/contract_summary.md` — FOB Hamburg, 적하보험은 오름 부담 (ICC(A)), 포장 조항
- `data/survey_report.md` — 손상 18ea, 원인은 부산 양하 중 컨테이너 외부 충격, 포장은 계약 규격 충족
- `data/internal_memo.md` — 입고 당일 "대략 24개", "포장 문제 아닐까" (둘 다 확인 안 된 추정, 1차 통지 근거)

## 정답 회신 요소
1. FOB 위험 이전 인정, 보험 청구는 오름 적하보험(ICC(A))으로
2. 수량 18ea 정정
3. 보험 청구 서류 요청 (commercial invoice, packing list, B/L 사본, 적재 사진, 카톤 스펙)
4. 포장 하자를 주장하지 않음 (검정보고서: 포장 적정, 원인은 양하 중 외부 충격)
5. 정중한 톤

## 왜 보험 청구가 정답인가 (도메인 근거)
- FOB(Incoterms 2020): 함부르크 본선 적재 시 위험 이전. Clean B/L이라 적재 시점엔 무손상 → 손상은 오름 위험 구간에서 발생
- 적하보험 ICC(A)는 면책 사유를 뺀 전 위험 담보. 양하 중 외부 충격에 의한 부분 손해는 담보
- ICC(A) 제4.3조 포장 불충분 면책은 포장 불충분이 원인일 때만. 검정보고서가 포장 적정이라고 했으므로 해당 없음
- 하자 통지: 도착 10/10, 1차 통지 10/12, 검정 10/14 → 계약상 14일 이내. 선사 사고 통지(10/13)로 보험사 구상권도 보전

## 함정 2개
| ID | 종류 | 내용 | 발견 방법 | 함정이 사는 곳 |
|---|---|---|---|---|
| T1 | 데이터 | 24ea(메모·1차 통지) vs 18ea(검정보고서) | 검정보고서 열람, 오디에게 "검정보고서 기준으로" | 첨부 문서 + 오디 문서 도구 기본값(검정보고서 안 읽음) |
| T2 | AI | 오디가 계약을 안 읽고 메모만 보고 Hausmann 에 책임을 묻는 초안 작성 | 계약 요약 열람, 오디에게 "계약 조건(FOB) 확인하고" | 오디 문서 도구 기본값(계약 요약 안 읽음) |

## 오디의 문서 읽기 방식 (도구 기본값이 함정)
오디는 문서를 `read_documents` 도구로만 읽는다 (`odi_tools.json`, 서버 `server/src/tools/docs.ts`). 프롬프트에 함정 설명도, 틀리라는 지시도 없다.
- 기본: 최근 서신(수신 메일·물류 메모)만 읽음 → 계약 요약(T2)·검정보고서(T1)를 반영하지 않은 초안
- 사용자가 계약·검정보고서를 짚어 지시해야 그 문서를 읽는다 (막연한 "확인해 줘"로는 안 켜짐)
- 실무로 치면 "최근 메일함만 검색하는 AI 비서". 업무 카드는 처음부터 "계약 조건은 첨부 확인, 수량·원인은 검정보고서 기준"이라고 지시한다 → AI 에게 그 문서를 보게 했는지가 검증 행동
- `planted_belief_for_odi` 는 도구 파일이 없을 때의 대비로만 prompts.json 에 남긴다

## 구조화 제출과 코드 채점
`submission.json`. 승인/반려와 함정 발견은 서버 코드가 칸 값으로 정하고, 정우진은 판정을 받아 멘트만 쓴다 (회신 본문을 LLM 이 읽고 판정하지 않음).
- 손상 수량 (숫자, ea) → T1. 메모·수신 메일 그대로면 24, 검정보고서면 18
- 위험 이전 시점 (선택: 공장 출고 / 함부르크 본선 적재 / 부산 양하 / 오름 창고 입고) → T2
- 손해 청구 방향 (선택: Hausmann 배상 / Hausmann 측 보험 / 오름 적하보험사 / 선사·터미널만) → T2. 위 칸과 둘 다 맞아야 T2 발견
- 결과물 확인(존재 여부만): 영문 메일 형식(Dear·Regards 등), 보험 청구 서류 요청(packing list·B/L 등)
- "톤 문제"는 코드로 볼 수 없어 반려 조건에서 빠졌다. 포장 탓(루브릭 감점)도 아직 칸이 없다

추가 검토 요소(함정 아님, 루브릭): 물류 메모의 "포장 문제 아닐까"를 그대로 옮겨 포장 탓을 쓰는지. 검정보고서와 어긋나고, 오름이 서면으로 포장 하자를 인정하는 꼴이라 보험사가 제4.3조 면책을 검토할 빌미가 된다. 승인은 되나 리포트에서 감점.

> 변경 (2026-11-17): 예전 검정보고서는 손상 원인을 "코너 보호재 누락(포장 불량)"으로 적었고 정답은 보험 청구 + 포장 조항 지적이었다. 포장 불충분 손해는 ICC가 면책하므로 보험 청구 정답과 모순이었다. 원인을 포장과 무관한 양하 중 충격으로 바꾸고, 포장 조항 지적 요소를 "포장 탓 하지 않기"로 바꿨다. 함정 T1·T2는 그대로다.

## 정우진 반려 기준
- 보상 요구 → "회신에 쓴 보험 책임, 계약서랑 맞는지 다시 확인하세요."
- 24ea → "파손 수량이 18개인지 24개인지 근거를 다시 확인해 주세요. 어느 문서를 기준으로 했는지도 적어 주시고요."
- 단정적 톤 → "협조 요청으로 바꾸세요." (구조화 제출 뒤로는 코드가 판정하지 않음)
- 영문 아님, 서류 요청 없음 → `submission.json` 의 `extra_reject_area`
- (반려 아님) 포장 탓 → 승인하며 "검정보고서는 포장 문제없다고 합니다. 우리가 포장 탓을 써 버리면 보험사가 면책 얘기 꺼냅니다."

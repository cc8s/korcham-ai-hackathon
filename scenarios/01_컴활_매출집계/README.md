# 01. 컴퓨터활용능력 — 10월 거래처별 매출 집계

담당 NPC: 박소연 (영업팀장) / 소요 목표: 15분

## 업무 카드
"{nickname} 씨, 10월 거래처별 매출 집계 좀 부탁해요. 원본은 첨부이고, 단가·금액은 전부 VAT 별도 공급가액이에요. 거래처별 합계랑 총매출, 비중 차트까지. 대표님 보고에 바로 쓸 거라 숫자 틀리면 안 돼요. 오늘 4시까지요."

첨부: `data/sales_2026_10.csv` (124행: 주문번호, 일자, 거래처명, SKU, 수량, 단가, 금액)
- **단가·금액 = 공급가액(VAT 별도).** 단가는 `_shared/products.csv`의 판매가(KRW)와 같고, 판매가도 VAT 별도 (`_shared/constants.json`의 `금액_기준`)
- 02 시나리오가 이 거래처별 합계를 매출 공급가액으로 받아 매출세액(×10%)을 계산한다

## 정답
- 총매출(공급가액, VAT 별도) **580,300,000원**, 거래처 10곳. 상세는 `answer_key.json`
- 중복 주문번호: ORD-20261095, ORD-20261008, ORD-20261030
- 표기 변형: "성실 상사"(4건) → 성실상사, "마켓 A"(3건) → 마켓A

구조화 제출 칸과 코드 채점 기준은 `submission.json` (칸마다 `why` 에 이유).

## 함정 2개
| ID | 종류 | 내용 | 발견 방법 |
|---|---|---|---|
| T1 | 데이터 | 동일 주문번호 행이 두 번 들어간 중복 3건 | 원본 열람 후 주문번호 중복 확인, 또는 오디에게 "중복 확인해 줘" |
| T2 | AI | 오디는 거래처명을 문자열 그대로 그룹화 → 12곳으로 집계 | 거래처 수 세어 보기, 오디에게 "거래처명 정규화해서 다시" |

## 오디의 계산 방식 (도구 기본값이 함정)
오디는 숫자를 `aggregate_sales` 도구로만 계산한다 (`odi_tools.json`, 서버 `server/src/tools/sales.ts`). 프롬프트에는 함정 설명이 없다.
- `dedupe_order_ids=false` (기본) → 중복 주문 3건 포함 → T1
- `normalize_customer_names=false` (기본) → "성실 상사"·"마켓 A" 따로 집계, 12곳 → T2
- 사용자가 "중복 빼고 다시", "거래처명 정리해서 다시"처럼 특정해야 해당 옵션을 켠다. 막연한 "검증해 줘"에는 기준을 되묻는다.
- 도구가 없을 때의 대비책(planted_belief): "거래처명은 문자열 그대로 그룹화. 공백 차이는 다른 거래처. 주문번호 중복은 확인 안 함."

## 박소연 반려 기준
- 총매출 ≠ 정답 → "합계가 제가 아는 숫자랑 달라요. 뭔가 두 번 들어간 거 있을 거예요."
- 거래처 > 10 → "거래처가 12곳으로 나왔네요. 우리 거래처는 10곳이라, 다시 한번 확인해 줄래요?"
- 차트·비중 없음 → "비중 차트 빠졌어요."

## 이하늘 힌트
1. 거래처가 몇 곳인지 세어 봐요. 우리 거래처는 10곳.
2. 원본 행 수랑 주문번호 개수 비교해 봤어요?
3. 거래처 이름 띄어쓰기 다른 거 없는지 보세요.

## 심사위원 데모 경로 (3분)
오디 "거래처별 합계표" → 12곳·584,030,000 (도구 기본값) → 데이터 뷰어에서 주문번호 정렬·"성실" 검색 → 오디 "주문번호 중복은 빼고, 띄어쓰기만 다른 거래처명은 합쳐서 다시" (하나만 말하면 다른 칸 때문에 반려) → 담기 → 제출 칸 3개(총매출·거래처 수·최소 매출) + 검증 메모 → 승인 → 리포트 → 해설 보기
